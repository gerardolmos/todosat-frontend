# Quickstart — validación local prevista (no ejecutada)

1. Tras autorización de IMPLEMENT, desde frontend registrar HEAD, status y hashes de archivos ajenos/SVG en `specs/010-operator-visual-adjustments/baseline.json`. No leer .env. Usar node y dependencias instaladas; no instalar nada.
2. Crear harness propio `tests/operator-visual-adjustments/render.mjs`: copia temporal mínima, fixtures sintéticos, assets locales, sin .env ni servicios reales. Renderizar los dos componentes reales y CSS correspondiente, no una maqueta. Fallar ante destinos no locales. Reutilizar patrones de harness existentes por lectura sin modificar Features 008/009.
3. Comandos previstos tras crear los archivos: `node --test tests/operator-visual-adjustments/presentation.test.mjs` y `node tests/operator-visual-adjustments/render.mjs`. El segundo genera únicamente muestra aislada local para estas dos superficies, no ejecuta QA general ni build productivo. Evidencias en qa.md.
4. US1: bandas presentes/ausentes/vacías/null, caracteres `<script>`, otras cinco características; comprobar HTML escapado, icono único original y mismo render 48 × 48. Comparar hash del SVG.
5. US2: fixtures de logos con alpha 1200×200, 200×200, 200×600; dimensiones editoriales presentes/ausentes; operadores con/sin logo y selección consecutiva; descripción larga. Con espacio suficiente, resultados visibles esperados 330×55, 110×110 y aproximadamente 36.67×110. Con A=180: 180×30, 110×110, 36.67×110. Ver contrato para otros anchos.
6. En muestra real local, validar 320, 768, 1280 y 1440 px: panel oculto en primeras dos, visible en últimas dos según breakpoint xl vigente. Medir posición relativa anterior/nueva (+35,+35), imagen visible y área, ausencia de overflow/recortes, texto largo y botón accesibles. Preservar minitarjetas. Comparación antes/después limitada a estas superficies, sin reabrir features.
7. Sin Chrome automatizado. Si no puede acreditarse geometría mediante herramientas disponibles, preparar URL solo 127.0.0.1 y solicitar revisión manual agrupada del propietario; registrar esa parte PENDIENTE hasta evidencia. Las pruebas matemáticas o de marcado no sustituyen esta comprobación.
8. Comparar hashes de 008/009, SVG y archivos ajenos; revisar diff y `git diff --check`. Documentar revisión exacta, resultados y límites. No commits, push, despliegue ni CONVERGE implícito.
